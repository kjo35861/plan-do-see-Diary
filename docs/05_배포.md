# 배포 — plandusy-diary

## 배포처 비교

| 배포처 | 장점 | 단점 | 채택 여부 |
|---|---|---|---|
| Vercel | 정적 사이트 무빌드 배포, GitHub 연동 시 자동 배포, 커스텀 도메인/HTTPS 기본 제공 | 없음(이 규모에선 단점 거의 없음) | **채택** |
| GitHub Pages | 완전 무료, 설정 단순 | 배포 반영이 상대적으로 느림, 프로젝트 루트 구조 제약(`docs/` 등)이 있을 수 있음 | 대안으로 가능하나 미채택 |
| Netlify | Vercel과 유사한 정적 배포 | 이번 과제에서 추가로 얻는 이점 없음 | 미채택 |

## 선택 근거

- 이 프로젝트는 Next.js 빌드 과정이 없는 순수 정적 사이트(HTML/CSS/JS)이므로 Vercel의 "Other" 프리셋으로 빌드 명령 없이 그대로 배포 가능.
- 환경변수(Supabase URL/키)가 필요 없음 — `config.js`에 이미 publishable key가 하드코딩되어 있고, 이 키는 노출돼도 안전한 공개용 키이기 때문(RLS가 실제 방어선).
- GitHub 연동 시 커밋마다 자동 재배포되어 이후 문서/코드 갱신 흐름과 맞음.

## 절차

1. 이 프로젝트 폴더를 GitHub 저장소로 push.
   ```bash
   git init
   git add .
   git commit -m "plandusy-diary 초기 커밋"
   git branch -M main
   git remote add origin <저장소 URL>
   git push -u origin main
   ```
2. vercel.com 로그인 → "Add New..." → "Project" → 위 GitHub 저장소 선택.
3. Framework Preset: **Other** (빌드 명령/출력 디렉토리 비워둠, 루트 그대로 배포).
4. Deploy 클릭 → 완료 후 발급된 `https://<프로젝트>.vercel.app` 주소가 결과물 URL.
5. 배포 후 시크릿 창에서 접속해 로그인 없이 바로 열리는지 확인(T06-C01).
6. `README.md`의 "결과물 주소"·"소스 주소"를 방금 얻은 URL로 채운다.

## 배포 전 최종 점검

- [ ] `config.js`에 secret key가 아닌 publishable key만 있는지 확인
- [ ] `.gitignore`에 민감 파일이 빠짐없이 들어있는지 확인 (현재는 커밋해도 되는 파일뿐이라 실질적으로 제외할 게 없음)
- [ ] 배포된 URL의 각 5개 페이지(계획/할 일/실행 기록/돌아보기/내보내기)가 모두 정상 접속되는지 확인
