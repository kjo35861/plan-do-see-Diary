# 기획 — plandusy-diary

## 기술 스택

- 프런트엔드: 순수 HTML/CSS/JS (빌드 도구 없음). `<script type="module">`로 ESM 사용, Supabase JS는 `https://esm.sh/@supabase/supabase-js@2` CDN에서 직접 import.
- 데이터베이스: Supabase(Postgres). 클라이언트가 publishable key로 RLS를 통과해 직접 REST 호출.
- 인증: 없음(과제 요구사항).
- 배포: Vercel (정적 사이트, 빌드 명령 불필요).

Next.js + `@supabase/ssr`(쿠키 기반 세션) 조합은 채택하지 않음 — 로그인/세션이 없는 과제라 서버 세션 관리 자체가 불필요하기 때문. 근거는 `트러블슈팅.md` 참고.

## 화면 구조 (역할별 5페이지)

```
index.html   — 계획 관리 (홈)
todos.html   — 할 일 관리 (선택된 계획 기준)
logs.html    — 실행 기록 (선택된 계획의 할 일 기준)
review.html  — 돌아보기 (계획 단위 집계 + 드릴다운 + 이관)
export.html  — 전체 자료 내보내기 + 안전성 점검 안내
```

공통 로직(`supabase` 클라이언트, DOM 유틸, KST 시간 변환, "선택된 계획" 로컬 상태)은 `shared.js`에 모아 5개 페이지가 공유한다. "선택된 계획"은 `localStorage`에만 저장되는 화면 이동 편의용 상태이며, 실제 다이어리 데이터는 항상 Supabase에 저장된다.

## 데이터베이스 스키마

전체 계약은 `contracts/pds-schema-v2.json` 참고. 요약:

- `plans` — 계획 원본. UPDATE 시 트리거가 이전 값을 `plan_revisions`에 자동 저장(계획 ID는 그대로 유지).
- `todos` — 계획에 딸린 할 일. `status`(active/done), 소프트 삭제(`is_deleted`).
- `execution_logs` — 실행 기록. `todos`/`plans`를 절대 덮어쓰지 않는 별도 테이블.
- `completion_events` — 완료 처리 이벤트 로그. 중복 클릭 방지 검증용.
- `carryover_notes` — 돌아보기에서 다음 계획으로 넘기는 메모.

## 핵심 알고리즘

### 완료 중복 방지 (`fn_complete_todo`)
```sql
select status into v_status from todos where id = p_todo_id for update; -- 행 잠금
if v_status = 'active' then
  update todos set status='done', completed_at=now() where id = p_todo_id;
  insert into completion_events (todo_id) values (p_todo_id);
end if;
-- 이미 done이면 아무 것도 하지 않음
```
버튼을 잠그는 클라이언트 방어만으로는 동시/연타 요청을 완전히 막을 수 없어, Postgres 함수 안에서 행 잠금 후 상태를 확인하고 나서만 삽입하도록 구현했다.

### 돌아보기 집계 (계획 단위)
```
계획 수  = 해당 plan_id의 is_deleted=false todos 수
완료 수  = 그중 status='done' 수
지연 수  = status != 'done' AND due_date < 오늘(Asia/Seoul)
막힘 수  = execution_logs.blocker_reason이 비어있지 않은 로그가 연결된 todo 수
예상 합계 = todos.estimated_minutes 합
실제 합계 = 연결된 execution_logs.actual_minutes 합
차이     = 실제 합계 - 예상 합계 (없으면 0)
```
"오늘" 판정은 `Intl.DateTimeFormat("en-CA", { timeZone: "Asia/Seoul" })`로 계산해 서버가 어느 시간대에 있든 항상 한국 기준 날짜를 쓴다.

### 다음 계획 이관
돌아보기에서 저장한 메모(`carryover_notes`, `applied_to_plan_id = null`)가 있으면, 새 계획을 만들 때 자동으로 `success_criteria` 앞에 붙이고 해당 메모를 "적용됨"으로 표시한다.

## 보안

- RLS: 모든 테이블에서 활성화. publishable key로 select/insert/update만 허용, delete 정책 없음 → 하드 삭제 불가.
- XSS: DOM 구성 시 `textContent`만 사용(`innerHTML` 미사용)하여 사용자 입력이 스크립트로 실행되지 않도록 함.
- 비밀키: 클라이언트에는 publishable key만 존재. secret key는 프로젝트 어디에도 포함하지 않음.
