# 플랜두씨 다이어리 (T06)

계획(Plan) → 실제로 한 일(Do) → 돌아보기(See)가 하나로 이어지는 개인 다이어리. 로그인 없음. 자료는 Supabase(Postgres)에 저장.

## 규칙

- 로그인/인증 기능을 추가하지 않는다 (7번 과제에서 다룰 범위).
- 계획을 수정해도 원래 값이 사라지면 안 된다 — DB 트리거로 이전 값을 자동 보존한다.
- 완료 처리 같은 "중복되면 안 되는" 동작은 클라이언트 방어(버튼 비활성화)만으로 끝내지 않고, DB 함수(행 잠금)로 서버측에서도 보장한다.
- 사용자 입력은 항상 `textContent`로만 렌더링한다 (`innerHTML` 금지).
- secret key(`sb_secret_...`)는 어떤 파일에도 넣지 않는다. publishable key만 사용한다.

## 짧은 확인 방법

1. 어디로 가나요 — 위 결과물 주소로 들어갑니다.
2. 세 단계 안에 무엇을 하나요 — ① "계획" 화면에서 계획 하나를 "이 계획 선택" ② "할 일" 화면 표에서 할 일 하나를 "완료"로 바꿈 ③ "돌아보기" 화면에서 해당 계획을 선택하고 "집계 계산"을 누릅니다.
3. 무엇이 보이면 통과인가요 — 완료 수가 1 늘어나고, 집계 카드의 숫자를 누르면 그 숫자를 구성한 실제 할 일 목록이 아래에 펼쳐집니다.
4. 안 될 때는 무엇이 보이나요 — 브라우저 콘솔에 Supabase 오류 메시지가 뜨거나, 표/집계가 계속 "-"로 남아 있고 새로고침해도 값이 채워지지 않습니다.

## AI와 내 판단

1. AI에게 맡긴 일 — 데이터베이스 스키마 설계(테이블·관계·제약), 완료 중복 방지를 위한 Postgres 함수/트리거 작성, 프런트엔드(HTML/CSS/JS) 전체 코드 작성, Supabase RLS 정책 작성.
2. 내가 직접 판단한 일 — 실제로 어떤 계획·할 일·실행 기록을 넣을지 고르는 것, 완성된 화면이 실제로 요구사항대로 동작하는지 눌러보며 확인하는 것, 배포 방식(Vercel) 선택.
3. AI 제안을 따르지 않은 일 — (실제로 다르게 판단한 부분이 있다면 여기에 적으세요. 없다면: 이번 과제 범위에서는 AI가 제시한 스키마/구조를 그대로 채택했습니다.)

## 완주 체크리스트

- [ ] 실제로 하고 있는 일 1개 이상을 계획으로 등록
- [ ] 그 계획에 할 일 5개 이상 등록
- [ ] 실행 기록 3개 이상 등록
- [ ] 돌아보기 화면 숫자가 전부 0이 아님을 확인
- [ ] 계획을 한 번 수정해 보고 "이력 보기"에 고치기 전 값이 남는지 확인
- [ ] 완료 버튼 연타 테스트 실행 후 결과가 1건인지 확인
- [ ] `<script>alert(1)</script>` 같은 문자열을 제목에 넣어보고 그대로 글자로 보이는지 확인
- [ ] 새로고침 후에도 모든 값이 그대로인지 확인
- [ ] "내 자료 내보내기"로 JSON 파일 다운로드 확인
- [ ] .env / config.js에 secret key가 아닌 publishable key만 들어있는지 확인
- [ ] 결과물·소스 URL을 새 시크릿 창에서 열어 로그인 없이 열리는지 확인
